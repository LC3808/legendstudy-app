## Engineering and product operating principle — Owner top-level rule

Future LegendStudy work must optimize for:

> **minimum cost, easiest viable solution, lightweight structure, concise
> implementation, maximum reuse of existing assets, expand only when actual need
> is demonstrated.**

Required work order:

1. Read Wiki/current status and relevant canonical domain documents first.
2. Inspect actual code/runtime state.
3. Reuse existing code, infrastructure, data and decisions where possible.
4. Choose the smallest solution that satisfies the user-facing requirement.
5. Validate the real path/device.
6. Expand investigation/architecture only at the observed failure boundary.

Avoid speculative or scale-premature engineering. Do not turn an MVP feature into
an infrastructure project because a theoretical attack exists. Authentication,
privacy, destructive data loss and other high-impact boundaries still require
appropriate safeguards, but security effort must be proportionate to the actual
service threat model and must not silently displace the core user goal.

Codex/Claude/Luna usage follows the same rule: use the right tool when it adds
clear value; minimizing tool use is not the goal, **avoiding unnecessary work and
repeated investigation is**.
