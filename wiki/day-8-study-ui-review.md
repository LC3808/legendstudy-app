## 1. Executive assessment

현재 `lib/features/study/presentation/study_page.dart` 는 Day 5 shell 그대로이며, 타이머 로직·상태·저장이 전부 없습니다. `[코드]` 따라서 이번 리뷰는 "기존 구현의 결함 지적"이 아니라 **Day 8-A 가 무엇을 만들어야 하는지의 UI 계약을 고정하는 작업**입니다.

핵심 판단 세 가지:

**(1) 지금 파일의 배치 순서를 그대로 확장하면 요구사항을 위반합니다.**
현재 순서는 `AppHeader → CompactUtilityCard(오늘 공부시간, 테두리 있음) → SectionHeader(공부 타이머) → 타이머 텍스트(테두리 없음) → 버튼` 입니다. `[코드]` 테두리·배경이 있는 카드가 타이머보다 **위에** 있고, 타이머는 시각적 컨테이너가 없습니다. "타이머가 화면에서 가장 강한 시각 요소여야 한다" 와 정면으로 충돌합니다. 이건 Codex가 자연스럽게 기존 파일을 확장하면 그대로 굳어지는 구조라 P0입니다.

**(2) DB 제약이 이미 production에 적용되어 있으므로, UI가 만들 수 있는 상태의 범위가 이미 정해져 있습니다.**
`20260914000100_study_sessions.sql` 은 `duration_seconds >= 1`, 스팬 ≤ 24시간, `active_segments` ≤ 256, `mode='study'` 일 때 `planned_duration_seconds IS NULL`, UPDATE 권한 없음을 강제합니다. `[DDL]` 이 네 가지는 각각 **UI에 종착 상태가 정의되어 있지 않으면 저장이 조용히 실패하는** 경계입니다. 특히 "일반 타이머에 목표 시간 입력 UI를 만들면 저장 자체가 거부된다"는 건 Codex가 모르면 반드시 밟는 지뢰입니다.

**(3) 저장 결과는 3종인데 UI 언어는 아직 1종입니다.**
게스트 로컬 저장 / 로그인 클라우드 저장 성공 / 로그인 저장 대기(실패 포함) 는 서로 다른 상태입니다. `[명세]` 8-A에서 "저장 완료" 단일 토스트를 만들면 8-B에서 전부 다시 만들어야 하고, 그 사이 기간에는 "저장 실패가 성공처럼 보인다"는 금지 조건을 위반합니다.

대규모 visual redesign은 필요 없다는 판단에 동의합니다. 컬러·타이포·카드 컴포넌트는 Day 5~7 과정에서 정리되었고 (`cardBorder` 가 `#EEEEEE` → `#DCDCDC` 로, '자료' 탭 `selectedIcon` 누락이 보완된 것 확인) `[코드]`, 이번에 필요한 건 **배치 순서·상태 언어·경계 처리** 세 가지입니다. 신규 컴포넌트는 4개면 충분합니다 (§14).

### P0-2. 저장이 거부되는 4개 경계에 UI 종착 상태가 없다 `[DDL]`

production에 적용된 제약과, 그에 대응해 UI가 반드시 가져야 할 종착 상태:

| # | DDL 제약 | 위반 시 결과 | 필요한 UI 종착 상태 |
|---|---|---|---|
| a | `duration_seconds >= 1` (활성 합계 < 1000ms) | INSERT 거부 | 저장 시도하지 않고 폐기 + idle 복귀 |
| b | `ended_at - started_at <= interval '24 hours'` | INSERT 거부 (활성 시간이 짧아도 거부) | `started_at + 24h` 에서 자동 종료·확정 |
| c | `jsonb_array_length(active_segments) > 256` → 함수 raise | INSERT 거부 | 256번째 구간 도달 시 '계속하기' 비활성 |
| d | `mode='study'` 는 `planned_duration_seconds IS NULL` 필수 | INSERT 거부 | **일반 타이머에 목표 시간 입력 UI를 만들지 않는다** |

**제안 (REQUIRED)**
- **(a)** 종료 시 활성 합계 `< 1000ms` 이면 저장 시퀀스를 시작하지 않는다. 에러 다이얼로그를 띄우지 않는다. 스낵바 1개: `기록하기에 너무 짧아요.` 후 idle 복귀. `[명세]` 와 일치 (under-one-second records discarded locally).
- **(b)** (b)는 **활성 시간이 아니라 벽시계 스팬** 기준임을 명시한다. 09:00 시작 → 일시정지 → 다음날 09:01 종료는 활성 2시간이어도 저장 불가입니다. 따라서 `started_at + 24h` 도달 시 열린 구간을 그 시점으로 잘라 자동 확정하고, 다음 앱 실행 시 `24시간이 지나 자동으로 종료했어요.` 를 1회 안내한다.
- **(c)** 구간 240개에서 경고 1회 (`일시정지 가능 횟수가 얼마 남지 않았어요.`), 256개 도달 시 '계속하기' 버튼을 `onPressed: null` 로 두고 보조문구 `이번 기록은 종료해 주세요.` 를 표시한다. '종료'는 항상 활성이어야 한다.
- **(d)** Day 8-A 일반 타이머 화면에 **목표 시간 / 예상 시간 / 계획 시간 입력 필드를 만들지 않는다.** 목표 시간 개념은 모의고사 모드 전용이다.

**근거**: (d)는 UI 설계자가 "타이머니까 목표 시간이 있으면 좋겠다"고 자연스럽게 추가할 수 있는 요소인데, DDL이 이를 거부합니다. 구현 후 발견하면 화면 하나를 되돌려야 합니다.

### P0-3. 상태별 액션 영역 규격이 없다 — 레이아웃 점프와 360px 오버플로가 확정적으로 발생한다 `[계산]`

상태별 버튼 구성이 1개 → 2개 → 1개로 바뀝니다. 규격이 없으면 상태 전이마다 액션 영역 높이가 달라지고, 그 위의 타이머가 위아래로 튑니다.

**계산 1 — 2× 텍스트 배율에서 가로 오버플로**
콘텐츠 폭 = 360 − `pagePadding 20`×2 = **320px**. `[코드]`
2버튼 Row(gap 12) → 버튼당 154px.
'일시정지' 4자 × 14sp = 56px, 2× 배율 시 112px + `FilledButton` 기본 가로 패딩 24×2 = 48px → **160px > 154px**. **오버플로 확정.**

**계산 2 — 세로 예산 (360×640, Running 상태)**
사용 가능 본문 높이 = 640 − status 24 − `NavigationBar` 80 = **536px**.

| 요소 | 높이 |
|---|---|
| ShellPage 상단 패딩 | 20 |
| AppHeader (headlineSmall 24sp≈32 + gap 8 + bodyMedium 21 + sectionGap 24) | 85 |
| 타이머 슬롯 (고정) | 100 |
| 상태 라벨 + gap | 30 |
| 액션 영역 | 56 |
| gap | 24 |
| 오늘 요약 1줄 | 21 |
| SectionHeader(최근 7일) | 52 |
| 7일 그래프 | 88 |
| 하단 패딩 | 20 |
| **합계** | **496 / 536** |

→ 기본 배율에서는 Running 전체가 스크롤 없이 들어갑니다 (여유 40px). 2× 배율에서는 타이머 + 액션 영역까지(20+138+100+48+72 = **378 / 536**)가 첫 화면에 유지되고 7일 그래프만 스크롤로 밀립니다. 이 정도면 허용 가능합니다.

**제안 (REQUIRED)**
- 액션 영역을 **고정 높이 56px 슬롯**으로 정의하고, 버튼이 1개든 2개든 이 높이를 유지한다.
- `MediaQuery.textScaler.scale(14) >= 21` (배율 1.5 이상) 이면 Row → Column 으로 전환하고, 이때만 슬롯 높이를 `56 → 120` 으로 확장한다. 타이머는 슬롯 위에 있으므로 확장은 아래 방향으로만 일어난다.
- 2버튼 배치는 `Expanded` + `gap 12` 로 균등 분할한다. 폭 고정값을 쓰지 않는다.
- 버튼 순서는 상태와 무관하게 **[좌: 비파괴 액션] [우: 종료]** 로 고정한다. (running: 일시정지 | 종료 / paused: 계속하기 | 종료) — 위치가 바뀌면 오터치가 납니다.

### P0-4. 타이머 숫자 표기 규격이 없다 — 현재 스타일에 `FontFeature.tabularFigures()` 가 없다 `[코드][계산]`

현재: `TextStyle(fontSize: 48, fontWeight: FontWeight.w600)` `[코드]`. `fontFamily` 를 앱에서 지정하지 않으므로 iOS는 SF Pro로 렌더링되고, SF Pro의 기본 숫자는 **비례폭(proportional)** 입니다. `00:00:00` 에서 `11:11:11` 로 갈 때 문자열 폭이 줄어듭니다.

추가로, 이 텍스트는 `FittedBox(fit: BoxFit.scaleDown)` 안에 있습니다 `[코드]`. **문자열 폭이 바뀌면 FittedBox 스케일이 바뀌고, 숫자 전체 크기가 매초 미세하게 진동합니다.** 비례폭 + FittedBox 조합은 가로 흔들림이 세로 크기 변화로까지 번지는 최악의 조합입니다.

**폭 계산**: `00:00:00` = 숫자 6 × 0.60em + 콜론 2 × 0.28em = 4.16em → 48sp × 4.16 = **200px** (콘텐츠 320px 대비 여유 120px). 2× 배율 시 399px → FittedBox가 320/399 = 0.80배로 축소 → **실효 77sp**. 배율이 2.0이 아니라 1.6으로 눌리지만 본문 14sp 대비 여전히 5.5배이므로 정보 손실은 없습니다. `[계산]`

**제안 (REQUIRED)**
- `fontFeatures: [FontFeature.tabularFigures()]` 를 타이머 텍스트 스타일에 추가한다.
- 표기 형식을 **항상 `HH:MM:SS` (시 2자리 zero-pad)** 로 고정한다. 1시간 미만이라고 `MM:SS` 로 줄이지 않는다 — 59:59 → 01:00:00 전이에서 폭이 바뀝니다. 24시간 상한이므로 시는 항상 2자리로 충분합니다. `[DDL]`
- 모의고사 카운트다운도 **같은 `HH:MM:SS` 형식**을 쓴다. 형식이 다르면 두 모드 사이에서 FittedBox 스케일이 달라져 시각 크기가 불일치합니다.
- 타이머를 `SizedBox(height: 100)` 고정 슬롯 안에 넣고 그 안에서 `FittedBox(scaleDown)` 을 쓴다. 슬롯 높이를 고정해야 배율 변화가 아래 요소를 밀지 않습니다.
- `letterSpacing` 을 지정하지 않는다 (tabular figures의 폭 계산을 깨뜨립니다).

### P0-5. 저장 결과 상태가 3종인데 UI 언어가 1종이다 `[명세][DDL]`

`study_sessions` 는 `authenticated` 에게 **SELECT / INSERT / DELETE 만** 부여하고 UPDATE 권한이 없습니다. `[DDL]` 즉 저장은 **한 번의 INSERT로 끝나거나, 같은 클라이언트 생성 UUID로 재시도(ignore-duplicates)** 하는 구조입니다. 저장 후 수정은 불가능합니다.

여기서 파생되는 사용자 가시 상태는 3종입니다:

| 상태 | 조건 | 라벨 (승인 필요) | 스타일 |
|---|---|---|---|
| S1 로컬 저장 | 게스트 | `이 기기에 저장` `[명세]` | textSecondary, 아이콘 없음 |
| S2 클라우드 저장 완료 | 로그인 + INSERT 성공 | `저장됨` | textSecondary + `Icons.check` 16px |
| S3 동기화 대기 | 로그인 + INSERT 미완/실패 | `동기화 대기` `[명세]` | textSecondary + `Icons.schedule` 16px |

**제안 (REQUIRED)**
- Day 8-A(로컬 전용) 단계에서 이미 **이 3상태를 표현할 수 있는 구조**로 만든다. 8-A에서는 S1만 렌더링되더라도 라벨을 상태 enum에서 받아오게 한다.
- "저장 완료" 라는 **단일 성공 문구를 쓰지 않는다.** S3를 S2처럼 보이게 만드는 가장 흔한 경로입니다.
- S3에서도 **측정된 시간은 그대로 보여준다.** 저장 실패가 곧 결과 소실이 아니라는 것을 화면이 증명해야 합니다.
- 색으로 구분하지 않는다. 세 상태 모두 `textSecondary #666666` (5.74:1) + 아이콘/문구로 구분한다. S3에 빨간색을 쓰면 사용자가 기록이 날아갔다고 오해합니다. `[계산]`

## 3. Study idle state

**현재** `[코드]`
```
AppHeader('학습', '한 번의 집중이 쌓이는 공간')
CompactUtilityCard('오늘 공부시간', '오늘 공부 기록이 아직 없어요.')

Text('공부 타이머를 곧 만나요. 기록 저장은 로그인 후 이용할 수 있어요.')
SectionHeader('최근 7일')
EmptyState('공부 기록이 쌓이면 일주일의 흐름을 볼 수 있어요.')
```

### 3-1. `SectionHeader('공부 타이머')` 제거 — **REQUIRED**
15sp w700 섹션 헤더가 48sp 타이머 바로 위에 붙어 있습니다. 타이머는 이 탭의 주제 그 자체이므로 라벨이 필요 없고, 헤더가 있으면 "여러 섹션 중 하나"로 읽힙니다. 제거 시 `top 24 + text 20 + bottom 8` = **52px 확보**. `[계산]`

### 3-2. 타이머 아래 상태 라벨 신설 — **REQUIRED**
헤더 대신 타이머 **아래** 12px 지점에 상태 라벨 1줄을 둔다. idle 문구: `시작할 준비가 됐어요`. 12sp `labelMedium` / textSecondary. 상태 전이가 이 한 줄에서만 일어나므로 사용자가 어디를 봐야 할지 학습됩니다.

### 3-3. `공부 시작` 버튼을 활성화 + 전폭 — **REQUIRED**
현재 `onPressed: null` 입니다 `[코드]`. 8-A에서 활성화하되, idle 액션 영역은 **1버튼 전폭**(320px)으로 둔다. Running의 2버튼과 폭이 달라지는 건 의도된 차이입니다 — "시작"은 유일한 선택지라는 신호입니다.

### 3-4. 안내 문구 교체 — **REQUIRED**
`공부 타이머를 곧 만나요. 기록 저장은 로그인 후 이용할 수 있어요.` 는 두 가지가 틀립니다. ① "곧 만나요"는 8-A 이후 거짓입니다. ② `[명세]` 상 게스트도 **이 기기에 로컬 저장**되므로 "저장은 로그인 후"는 사실이 아닙니다.

교체안 (PO 승인 필요):

### 3-5. idle에서 오늘 요약 문구 — **REQUIRED**

## 4. Running state

### 4-1. 레이아웃 — **REQUIRED**
```
AppHeader
[타이머 슬롯 100px]  00:12:34      ← 48sp w600 tabular
[상태 라벨]          공부 중
[액션 슬롯 56px]     [일시정지]  [종료]     ← Expanded 균등, gap 12
                     오늘 1시간 42분 공부했어요.   ← 14sp textSecondary
SectionHeader(최근 7일)
[7일 그래프]
```

### 4-2. 타이머 갱신 주기 — **REQUIRED**
초 단위 표시이므로 화면 갱신은 1초 주기. 단 **`setState` 범위를 타이머 텍스트 위젯으로 한정**한다 (`ValueListenableBuilder` 또는 타이머 전용 `Consumer`). 페이지 전체를 매초 리빌드하면 7일 그래프까지 매초 다시 그려집니다.

### 4-3. 백그라운드 복귀 시 점프 — **REQUIRED**
`[명세]` 상 실행은 monotonic clock 기반 로컬 durable 구조입니다. 복귀 시 타이머는 **애니메이션 없이 즉시 정확한 값으로 갱신**한다. 숫자를 굴리는 카운트업 애니메이션을 넣지 않는다 — 실제 경과와 표시가 어긋나는 구간이 생깁니다.

### 4-4. 탭 이동 시 동작 — **REQUIRED**
`StatefulShellRoute.indexedStack` 이므로 다른 탭으로 이동해도 Study 브랜치는 살아 있습니다 `[코드]`. 타이머는 계속 실행하고, 실행 상태는 화면이 아니라 로컬 저장소에 있으므로 탭 이동으로 손실되지 않습니다. **탭 이동 시 경고나 확인을 띄우지 않는다.**

### 4-5. 실행 중 주황색 사용 금지 — **REQUIRED** `[계산]`
"공부 중"을 강조하려고 타이머 숫자를 `primary #FFAC14`(1.88:1) 또는 `primaryDark #E99500`(2.40:1)로 칠하지 않는다. 둘 다 48sp large text 기준 3:1에도 미달합니다. 숫자는 항상 `textPrimary #202124` (16.10:1).

실행 중임을 나타내려면: 상태 라벨 앞에 8px `primary` 점(dot) 1개. 점은 장식이고 정보는 `공부 중` 텍스트가 전달하므로 대비 요건에 걸리지 않습니다.

### 4-6. 실행 중 점 깜빡임 — **DEFER**
살아있음 신호로 유용하지만, `prefers-reduced-motion` 대응이 필요하고 8-A 범위를 키웁니다. 8-C 이후.

### 4-7. 세션 제목/과목 입력 — **DEFER**
DDL이 `title`(80자) `subject`(40자)를 허용하지만 `study` 모드에서 둘 다 nullable 입니다 `[DDL]`. v1 일반 타이머는 입력 없이 시작하는 게 마찰이 가장 적습니다. 입력을 넣는다면 **시작 전이 아니라 종료 시트에서** 선택 입력으로 받아야 합니다 (시작을 막지 않기 위해). 8-D 이후.

## 5. Paused state

### 5-1. 일시정지가 "멈춘 상태"임을 숫자로 증명 — **REQUIRED**
일시정지 중 타이머 숫자는 **정지**한다. 정지한 숫자와 실행 중 숫자가 시각적으로 동일하면, 사용자는 앱이 멈춘 건지 기록이 멈춘 건지 구분할 수 없습니다.

구분 방법 (색상 변경 금지):
- 상태 라벨: `공부 중` → `일시정지됨`
- 상태 라벨 앞 dot 제거
- 타이머 숫자 `opacity 1.0 → 0.55`. `#202124` 를 흰 배경에 55% 합성하면 실효 `#8E8F91` ≈ **4.0:1**. 48sp는 WCAG large text 기준 3:1이므로 통과합니다. `[계산]`

### 5-2. 버튼 — **REQUIRED**
`[계속하기]  [종료]`. 좌/우 위치는 running과 동일 (P0-3). `계속하기` 는 `FilledButton`, `종료` 는 `OutlinedButton` 으로 시각 위계를 준다.

### 5-3. 256 구간 상한 UI — **REQUIRED** (P0-2c 재확인)
구간 240 도달: 상태 라벨 아래 12sp 보조문구 `일시정지 가능 횟수가 얼마 남지 않았어요.`
구간 256 도달: `계속하기` 비활성 + 보조문구 `이번 기록은 종료해 주세요.`
**`종료` 는 어떤 경우에도 비활성화하지 않는다.**

### 5-4. 장시간 일시정지 안내 — **RECOMMENDED**
일시정지 상태로 벽시계 기준 20시간 경과 시 (24시간 상한의 83%) 보조문구 `24시간이 지나면 자동으로 종료돼요.` 를 표시한다. `[DDL]` 상한이 활성 시간이 아니라 벽시계 스팬이므로, 일시정지 중에도 상한이 다가온다는 사실을 사용자가 알 방법이 달리 없습니다.

### 5-5. 일시정지 자동 해제 — **DEFER**
"5분 이상 일시정지면 자동 종료" 같은 정책은 v1에 넣지 않습니다. 사용자가 의도적으로 길게 쉬는 경우를 잘못 처리합니다.

## 6. Ending / save state

### 6-1. 종료는 1단계 bottom sheet — **REQUIRED**
`종료` → 확인 다이얼로그 → 저장 완료 토스트, 는 3단계로 마찰이 큽니다. 한 번의 bottom sheet에서 끝냅니다.

```
[bottom sheet]
  1시간 42분 공부했어요            ← 22sp w700 (titleLarge)
  09:12 – 10:58 · 일시정지 3회      ← 12sp textSecondary

  [ 기록 저장 ]                    ← FilledButton, 전폭, 48px
  [ 취소 ]                         ← TextButton
  [ 계속하기 ]                     ← TextButton
```

- `기록 저장` = completed, 저장 시퀀스 진입
- `취소` = cancelled, 총합에서 제외, 로컬에만 `취소됨` 으로 남김 `[명세]`
- `계속하기` = 시트 닫고 직전 상태(running/paused)로 복귀
- 시트 dismiss(배경 탭/스와이프) = `계속하기` 와 동일. **dismiss가 기록을 버리게 만들지 않는다.**

### 6-2. 1초 미만은 시트를 띄우지 않는다 — **REQUIRED** (P0-2a)
활성 합계 `< 1000ms` 이면 시트 없이 스낵바 `기록하기에 너무 짧아요.` + idle 복귀. 사용자에게 선택지를 주는 게 아니라 **DB가 거부하는 값**이므로 선택 UI 자체가 거짓말입니다. `[DDL]`

### 6-3. 저장 결과 표기 — **REQUIRED** (P0-5)
시트를 닫고 idle로 돌아간 뒤, 오늘 요약 줄 오른쪽에 상태 칩을 붙인다:
`오늘 1시간 42분 공부했어요.  [이 기기에 저장 / 저장됨 / 동기화 대기]`
칩은 12sp textSecondary + 16px 아이콘, 배경 없음. 전용 알림 배너를 만들지 않는다.

### 6-4. 저장 실패 — **REQUIRED**
- 에러 다이얼로그를 띄우지 않는다.
- 결과 시간은 그대로 표시하고 상태만 `동기화 대기` 로 둔다.
- 재시도 버튼을 사용자에게 노출하지 않는다 — 클라이언트 UUID 기반 ignore-duplicates 재시도는 자동이고 `[명세][DDL]`, 수동 재시도 버튼은 중복 INSERT 걱정을 사용자에게 떠넘깁니다.
- 예외: 동일 세션이 24시간 이상 `동기화 대기` 면 MY 탭에 안내 1줄. 8-B 범위.

### 6-5. 1분 미만 표기 — **REQUIRED**
1초~59초 기록은 `오늘 1분 미만 공부했어요.` `[명세]` 로 표기한다. `0분` 이라고 쓰지 않는다 — 저장된 기록을 0으로 표시하면 저장 실패로 읽힙니다.

### 6-6. 종료 후 화면 — **REQUIRED**
idle로 복귀하되 타이머는 `00:00:00` 으로 리셋한다. 직전 기록 시간을 타이머 자리에 남기지 않는다 (다음 시작 시 이어지는 것처럼 보입니다).

## 9. Guest / Authenticated UX

### 9-1. 게스트도 타이머 전 기능을 쓴다 — **REQUIRED**

### 9-2. 저장 위치를 숨기지 않는다 — **REQUIRED**
게스트 기록은 `이 기기에 저장` 으로 표기한다 `[명세]`. "저장됨" 으로만 쓰면 기기 변경 시 소실을 예고하지 않은 것이 됩니다.

### 9-3. 로그인 유도는 1곳, 비차단 — **RECOMMENDED**
Study 탭 최하단(7일 그래프 아래)에 1줄:
`로그인하면 기기를 바꿔도 기록이 이어져요.` + `TextButton('로그인')`
- 상단에 두지 않는다 (타이머 위계 침해)
- 저장 직후에 띄우지 않는다 (성취 순간을 가로챔)
- 게스트 기록이 0건이면 노출하지 않는다

### 9-4. 로그인 시 기존 게스트 기록 — **REQUIRED**
`[명세]` 상 **자동 import 하지 않는다.** 로그인 후에도 게스트 기록은 게스트 네임스페이스에 남고 `이 기기에 저장` 으로 표시된다.

문제: 로그인 직후 7일 그래프가 갑자기 비면 사용자는 기록이 사라졌다고 인식합니다.
**제안 (REQUIRED)**: 로그인 후 게스트 기록이 존재하면 그래프 아래 1줄 `로그인 전 기록 12건은 이 기기에 남아 있어요.` 를 표시한다. 가져오기 기능은 8-D 이후 — **DEFER**.

### 9-5. 실행 중 로그인 — **REQUIRED**
`[명세]` 상 소유권은 **시작 시점에 확정**됩니다. 게스트로 시작한 세션은 중간에 로그인해도 게스트 소유로 종료·저장된다. 이 세션의 저장 칩은 `이 기기에 저장` 이어야 하며, **로그인했다는 이유로 `저장됨` 으로 바뀌면 안 된다.**

### 9-6. 계정 전환 — **REQUIRED**
계정 A → B 전환 시 오늘 합계와 7일 그래프를 **즉시 비우고** B 기준으로 다시 계산한다. A의 값을 한 프레임이라도 B의 화면에 남기지 않는다. 전환 중에는 스켈레톤이 아니라 `불러오는 중` 1줄을 쓴다 (스켈레톤은 이전 값 형태를 유지해 오인을 부릅니다).

### 9-7. 실행 중 계정 전환 — **REQUIRED**
실행 중인 세션이 있으면 계정 전환 전에 확인한다: `공부 타이머가 실행 중이에요. 이 기록은 지금 계정에 저장돼요.` + `계속` / `취소`. 자동으로 세션을 종료시키지 않는다.

## 10. Focus / 방해금지 preference UX

> 이번 리뷰 범위는 **UI 구조만** 입니다. 실제 Focus 제어 구현은 8-C.

### 10-1. 프롬프트가 타이머 시작을 막지 않는다 — **REQUIRED**
`[명세]` 의 핵심 제약입니다. 구현 순서를 명시적으로 고정합니다:
1. `공부 시작` 탭 → **즉시** running 진입, `started_at` 확정, 타이머 숫자 증가 시작
2. 400ms 후 bottom sheet 표시
3. 시트의 어떤 선택도(닫기 포함) 타이머에 영향 없음

시트를 먼저 띄우고 선택 후 시작하는 구조를 **만들지 않는다.**

### 10-2. 프롬프트 내용 — **REQUIRED**
```
집중 모드를 사용할까요?
공부하는 동안 알림을 줄여요.

[ 항상 사용 ]      ← FilledButton
[ 이번만 ]         ← OutlinedButton
[ 사용하지 않음 ]   ← TextButton
```
- 시트 dismiss = `이번만` 도 `사용하지 않음` 도 아님 → 저장 없이 다음 시작 때 다시 물음
- `항상 사용` / `사용하지 않음` 은 기기 로컬 preference로 저장, 이후 묻지 않음 `[명세]`
- 저장된 선택은 MY 탭에서 변경 가능 — 8-C

### 10-3. Android — **REQUIRED**
- `AutomaticZenRule` 생성 가능 여부를 **먼저 확인**하고, 불가하면 시트를 **아예 표시하지 않는다.** 비활성 버튼이 있는 시트를 띄우지 않는다.
- 앱이 만든 자기 규칙만 조작한다 `[명세]`. 사용자의 기존 방해금지 설정을 읽거나 변경하지 않는다.
- 권한 요청이 필요하면 시트에서 바로 시스템 설정으로 보내지 않는다 — `항상 사용` 선택 후 다음 화면에서 안내한다.

### 10-4. iOS — **REQUIRED**
`[명세]` 및 지시서 명문: iOS는 앱이 Focus를 켤 수 없습니다.
- **`항상 사용` / `이번만` 버튼을 iOS에서 렌더링하지 않는다.**
- 집중 모드 **상태 칩(`집중 모드 켜짐` 등)을 어떤 조건에서도 렌더링하지 않는다.** 자동 제어를 지원하는 것처럼 보이는 모든 UI가 금지 대상입니다.
- 대신 idle 상태 하단에 안내 1줄만 둔다: `iOS는 앱이 집중 모드를 켤 수 없어요. 제어 센터에서 직접 켜 주세요.` `TextButton` 도 붙이지 않는다 (탭해서 켜질 것처럼 보임).
- 이 안내는 **1회만** 노출하고 닫으면 다시 띄우지 않는다 — **RECOMMENDED**

### 10-5. 집중 모드와 타이머 상태를 한 줄에 섞지 않기 — **REQUIRED**
상태 라벨(`공부 중` / `일시정지됨`)은 타이머 상태 전용입니다. 여기에 집중 모드 상태를 합치면 어느 쪽이 꺼진 건지 읽을 수 없습니다.

### 11-3. 시작 폼 — **REQUIRED**

### 11-4. 실행 화면 — **REQUIRED**
- 카운트다운은 **남은 시간 감소**, 형식은 일반 타이머와 동일한 `HH:MM:SS` (P0-4)

- 답안 입력 → 자동채점 → 점수 → 등급 확장은 **DEFER** (구조만 열어둠: `subject` 컬럼과 mock 전용 화면이 이미 분리되어 있음)

## 13. Accessibility

### 13-1. 타이머 숫자를 매초 읽지 않는다 — **REQUIRED** `[코드]`
현재 `Semantics(label: '공부 타이머, 대기 상태, 0시간 0분 0초', excludeSemantics: true)` 입니다. 이 label을 매초 갱신하면 TalkBack/VoiceOver가 초마다 전체 문장을 다시 읽습니다 — 스크린리더 사용자에게는 앱을 쓸 수 없게 만드는 수준의 결함입니다.

**제안 (REQUIRED)**
- 타이머 숫자 위젯: `ExcludeSemantics` 로 완전히 숨긴다
- 별도 `Semantics(label: ...)` 를 두고 **분 경계에서만** label을 갱신한다: `공부 중, 1시간 12분 경과`
- `liveRegion: true` 를 **쓰지 않는다** (자동 낭독 유발)
- 상태 전이(시작/일시정지/재개/종료/저장)에만 `SemanticsService.announce()` 를 1회 호출한다

### 13-2. 상태 전이 announce 문구 — **REQUIRED**
| 전이 | announce |
|---|---|
| → running | `공부를 시작했어요` |
| → paused | `일시정지됨` |
| → running (재개) | `다시 시작했어요` |
| → 저장 완료 | `1시간 42분 기록했어요` |
| → 너무 짧음 | `기록하기에 너무 짧아요` |

### 13-3. 터치 타깃 48px — 확인됨 `[코드]`
`textButtonTheme` / `outlinedButtonTheme` / `filledButtonTheme` 모두 `minimumSize: Size(48, 48)` 이 설정되어 있습니다. 신규 컴포넌트(프리셋 칩, 상태 칩)도 이 기준을 따라야 합니다. 상태 칩은 비인터랙티브이므로 예외입니다.

### 13-4. 색 의존 금지 — **REQUIRED**
- running vs paused: 색이 아니라 **라벨 텍스트 + opacity + dot 유무** (§5-1)
- 7일 그래프 오늘 강조: 색 + **라벨 굵기** (§8-2)
- 저장 3상태: 색이 아니라 **문구 + 아이콘** (§6-3)

### 13-5. 2× 텍스트 배율 — 검증됨 `[계산]`
- 타이머: FittedBox로 실효 77sp, 정보 손실 없음 (P0-4)
- 액션 영역: 1.5배 이상에서 Column 전환 (P0-3)
- 타이머 + 액션이 첫 화면에 유지됨 (378 / 536)

### 13-6. 대비 검증 결과 `[계산]`

|---|---|---|---|

## 16. Interaction flows

### 16-1. 일반 타이머 상태 기계

```
                    ┌──────────────────────────────┐
                    ▼                              │
   ┌────────┐  공부 시작   ┌─────────┐  일시정지  ┌────────┐
   │  idle  │ ──────────▶ │ running │ ─────────▶ │ paused │
   └────────┘             └─────────┘ ◀───────── └────────┘
        ▲                      │      계속하기        │
        │                      │ 종료                 │ 종료
        │                      ▼                      ▼
        │                 ┌──────────────────────────────┐
        │                 │  ending (bottom sheet)        │
        │                 └──────────────────────────────┘
        │                   │          │          │
        │      계속하기/dismiss│   기록 저장 │     취소  │
        │                   └──▶(직전 상태)  │          │
        │                                  ▼          ▼
        │                          ┌──────────┐  ┌──────────┐
        └──────────────────────────│  saving  │  │cancelled │
                                   └──────────┘  └──────────┘
                                    │        │
                       활성 <1000ms │        │ 활성 >=1000ms
                                    ▼        ▼
                        [스낵바 '너무 짧아요']  [칩: 이 기기에 저장
                                              / 저장됨 / 동기화 대기]
```

**자동 전이 (사용자 입력 없음)**
| 조건 | 전이 |
|---|---|
| 벽시계 스팬 24h 도달 | running/paused → ending(자동 확정, 기록 저장) |
| 구간 256 도달 | paused 에서 `계속하기` 비활성 |
| 앱 강제 종료 후 재실행, 체크포인트 명확 | → 직전 상태 복원 |
| 앱 강제 종료 후 재실행, 구간 모호 | → `recoveryRequired` |

### 16-2. 복구 흐름 (`recoveryRequired`) — **REQUIRED**

`[명세]` 상 문구는 `시간 기록을 확인해 주세요` 이고 원칙은 **"불확실한 공백을 자동으로 인정하지 않는다"** 입니다.

```
[bottom sheet]
  시간 기록을 확인해 주세요
  09:12에 시작한 기록이 있어요.
  확인된 시간은 1시간 12분이에요.

  [ 1시간 12분으로 저장 ]     ← FilledButton
  [ 이 기록 버리기 ]          ← TextButton
```
- **모호한 공백을 더해서 제시하지 않는다.** 확인된 시간만 제시합니다.
- dismiss 시 시트를 다음 실행에서 다시 띄운다. 미결정 상태로 조용히 폐기하지 않는다.
- 이 시트가 뜬 상태에서도 **새 타이머 시작을 막지 않는다** — 막으면 복구를 미룬 사용자가 앱을 쓸 수 없습니다. 새로 시작하면 복구 대상 기록은 `이 기록 버리기` 가 아니라 **보류 상태로 유지**하고 다음 실행에서 다시 묻는다.

### 16-3. 모의고사 상태 기계
```
idle(general) ──'모의고사 모드'──▶ mock form
                                      │ 시작 (title, planned 검증 통과)
                                      ▼
                                 mock running ◀──계속하기──▶ mock paused
                                      │  제출 / 카운트다운 0             │ 제출
                                      ▼                                  ▼
                                 mock ending (확인 시트)
                                      │ 제출 확정
                                      ▼
                                   saving → idle(general)
```
- mock form에서 뒤로가기 = general idle 복귀, 입력 폐기 (확인 없음 — 아직 아무것도 시작되지 않음)
- mock running 중 뒤로가기 = **모드 종료 아님**. Study 탭에 머무름. `제출` 을 거쳐야만 종료됩니다.

### 16-4. 첫 시작 시퀀스 (Focus 프롬프트 포함)
```
t=0ms     '공부 시작' 탭
t=0ms     started_at 확정, running 진입, 로컬 체크포인트 기록
t=0ms     타이머 00:00:00 → 증가 시작
t=400ms   Focus bottom sheet 표시 (Android + 지원 기기 + 미결정 상태에서만)
t=?       사용자 선택 or dismiss → 타이머에 영향 없음
```
**이 순서는 협상 대상이 아닙니다.** `[명세]`

### 16-5. 저장 시퀀스 (8-A 로컬 / 8-B 클라우드)
```
종료 확정
  → 활성 합계 계산 (구간 union)
  → < 1000ms ?  yes → 폐기 + 스낵바 + idle
                no  ↓
  → 로컬 트랜잭션 커밋 (클라이언트 UUID 생성)   [8-A 여기까지]
  → UI: 칩 '이 기기에 저장'(게스트) / '동기화 대기'(로그인)
  → 로그인 상태면 INSERT 시도 (ignore-duplicates)  [8-B]
  → 성공 → 칩 '저장됨'
  → 실패 → 칩 '동기화 대기' 유지, 자동 재시도, 사용자 개입 없음
```

## 19. Final verdict

Day 8-A 구현에 착수하기 전에 **§17의 A, C, D, E, F 다섯 가지 PO 결정**과 **P0-1 ~ P0-5 다섯 가지 UI 계약**이 확정되어야 합니다.

현재 Study 화면 자체에는 "버그"라 부를 결함이 없습니다 — Day 5 shell로서는 의도대로 동작합니다. 다만 이 shell을 그대로 확장하면 ① 시각 위계가 역전된 채 굳고 ② production DDL이 이미 거부하는 상태(1초 미만, 24시간 초과, 256 구간, 일반 모드 목표시간)에 대한 종착 UI가 없어 조용한 저장 실패가 발생하며 ③ 저장 결과 3상태를 8-B에서 다시 만들어야 합니다.

위 다섯 결정과 다섯 계약이 문서로 고정되면, 나머지는 §18의 36개 항목을 순서대로 실행하는 작업이며 신규 컴포넌트 4개로 충분합니다. 세로 예산(528/536 @ 360×640)과 대비비는 전부 사전 검증했으므로, 명세대로 구현하면 §13의 접근성 요건은 그래프 색 대비(§8-3 Semantics로 보완) 외에 추가 위반이 없습니다.

**FINAL VERDICT: B**
