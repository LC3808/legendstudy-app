# 학습용 5단계 평가 — Owner 승인 및 구현 기준

2026-11-04. **도입 승인 / 실제 생성·독립 검토 이력 PASS / TASK16-L 혼합 신규4단계 저장·History PASS / 실제 최초·재첨삭 비교 PARTIAL / 운영 미적용**.
[기존 결과 정책](final-feedback-ux-refinement-20261031.md), [수리 공통 계약](task16g-learning-loop-20261102.md), [장기 이력 보존](longitudinal-learning-admissions-data-strategy.md)을 계승한다. 기존 종합 별점 금지에서 이번에 승인한 범위만 변경한다.

## 확정된 경계

- 표시는 `학습 완성도 · 5단계`이며 별 모양을 사용해도 대학 공식 점수·백분율·합격 가능성으로 표현하지 않는다.
- 기존 대학별 평가 요소·공식 채점 기준을 우선한다. 단순 항목 평균, CORRECT→5, 오류 개수→등급 변환을 금지한다.
- 근거 부족, 불확실 전사, 미완료 평가, 공식 기준 연결 부족은 `판단 보류`이며 0단계/낮은 별점으로 바꾸지 않는다.
- 검증된 새 평가부터 기록한다. 기존 결과·공식 기준·History·이용권을 수정하거나 별점을 소급 생성하지 않는다.
- 인문·수리·혼합형은 같은 명칭과 설명 구조를 사용하되 문항 특성과 대학 기준을 보존한다. 일부 문항만 완료된 혼합형에 전체 완성도를 부여하지 않는다.

## 단계별 앵커 — 구현용 초안, 실제 사례 검증 필요

| 단계 | 표시 | 판단 근거 |
|---|---|---|
| 1 | 핵심 요구부터 확인 | 평가 가능한 답안이 있지만 공식 핵심 요구에 맞는 논증·풀이의 성취가 아직 확인되지 않음 |
| 2 | 기초 접근 형성 | 타당한 출발·일부 성취가 있으나 핵심 개념·조건·논증에 큰 보완 필요 |
| 3 | 핵심 풀이 발전 | 핵심 방향과 주요 성취가 확인되나 중요한 추론·계산·근거 보완이 남음 |
| 4 | 마무리 보완 | 핵심 요구는 충족하고 국소적인 설명·검산·조건 표현만 보완 필요 |
| 5 | 요구 충족 확인 | 검증 가능한 전체 요구와 타당한 대안 풀이를 포함해 주요 과정·결론·근거 충족 확인 |

5단계는 만점·합격·완벽함을 의미하지 않는다. 올바른 최종 답만으로 과정 충족을 추정하지 않는다. 잘못된 공식 예시나 OCR 불확실성을 학생의 낮은 단계로 전가하지 않는다. 대학별 중요도는 실제 기준에서 가져오며 없는 배점은 만들지 않는다.

## 공통 서버 계약 설계

기존 결과의 선택적 `learning_completeness` 확장으로 설계한다. 새 평가 엔진·별도 History는 만들지 않는다. 최소 항목은 policy_version, rubric_version, evaluation_id, assessed_at, status(ASSESSED/INSUFFICIENT_EVIDENCE), level(1–5 또는 null), rationale, criterion_evidence_refs, student_step_refs다. 클라이언트는 값을 계산하지 않는다. 근거 ID는 같은 문항·평가의 실제 공식 기준/학생 관측과 일치해야 한다. 독립 검토 실패 시 단계도 공개하지 않는다. 생성·검증·저장·APP/WEB 표시가 모두 연결되기 전 운영에 활성화하지 않는다.

최초·재첨삭 비교는 기존 attempt 연결을 사용하고 동일 문항·동일 기준 및 정책 버전에서만 전후 단계와 근거 변화를 보여준다. 기존 값이 없으면 `이전 평가에는 학습 완성도 없음`, 기준이 다르면 `평가 기준이 달라 직접 비교하지 않음`으로 표시한다. 이전 단계를 추정하거나 등급 차이를 성적 상승으로 표현하지 않는다.

## 보존 검토 7개

1. 새 평가 시점의 학습 판단이며 평가/기록 시각과 정책 버전을 보존한다.
2. 답안·공식 기준·평가 관측의 고정 ID와 버전에서 근거를 추적한다.
3. 과거 결과 UPDATE나 backfill 없이 새 평가에만 추가한다.
4. 기존 canonical 학생 및 attempt 소유권을 재사용한다.
5. Learning의 파생 판단이며 Decision/Outcome·입시 결과가 아니다.
6. 기존 본인 결과 접근·보존/삭제 정책을 그대로 적용하며 추가 개인정보를 수집하지 않는다.
7. 원본 사실과 분리한 versioned judgment로 기록하고 불확실성·비교 불가를 보존한다.

## 출시 전 검증

정답·계산 오류·개념 오류·논리 비약·미완성·대안 풀이·다수 오류·근거 부족, 최초/무료 재첨삭 비교, 인문/수리/혼합, 공개 전 정답 유출 차단을 검증한다. 단순 Mock 결과를 실제 품질 PASS로 취급하지 않는다. 이번 문서는 승인 범위와 설계이며 서버 저장·APP/WEB 별점 표시 완료 보고가 아니다.

후속 구현 범위와 실제 미완료는 [TASK16 최종 품질 보고](task16-final-quality-20261104.md)를 따른다.
