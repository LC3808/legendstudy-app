운영 함수 정의를 읽기 전용으로 확인했다. `admin_member_list`는 가입일 정렬만 지원하며 잔액을 반환하지 않는다. `admin_member_search`는 3자 이상 검색이 필수이고 가입일 정렬이다. 클라이언트 전체 회원 조회/재정렬은 사용하지 않는다.

## 최소 변경

`apply.sql`은 관리자 전용 조회 함수 1개만 추가한다. 기존 `admin_credit_snapshot`으로 만료·예약·취소 대기 구매분을 반영한 잔액을 계산한다. 이메일/UUID 검색, 10/20/50 서버 페이지네이션, 잔액 양방향/최근 지급/최근 소비/최근 가입 정렬을 제공한다. 동률은 UUID로 고정한다. 신규 테이블·인덱스·기존 함수 교체 없음. 데이터 쓰기 없음.

최근 이용일은 서비스 전체 활동일로 추정하지 않고 **최근 크레딧 사용일**로 표시한다. 로그인일은 별도 필드다. 무료는 기존 상세와 동일한 signup_bonus, 이벤트/보상/관리자 지급은 기타로 유지한다.

## 적용 결과

격리 PostgreSQL 17에서 권한 거부·동률 정렬·이메일/UUID 검색·10/20/50 페이지 경계·만료/예약/취소 대기 잔액 검증 PASS. Production 사전검사 후 신규 함수 적용, 사후검사 7개 true. 기존 잔액/지급 함수 정의 및 Ledger 90행·balance_delta 합계338 보존(적용 직후 기준). 전 회원의 잔액 집계는 서버에서 수행하므로 대규모 회원 성능은 별도 관찰 대상이며 신규 인덱스는 추가하지 않았다.

WEB은 이 RPC로 최상단 압축 테이블을 구성하고 기존 회원 상세 및 지급 폼을 재사용한다. 지급/회수/결제 취소 운영 테스트는 하지 않는다. RPC 배포 전 새 화면을 Production에 배포하지 않는다.

## 보존 검토 7항목

1. 기존 지급·소비·가입 시각만 조회한다.
2. 원장·원본 지급 내역을 변경하지 않는다.
3. 과거 이벤트와 잔액을 삭제/덮어쓰지 않는다.
4. auth.users UUID 및 기존 credit account 식별자를 재사용한다.
5. 학습/진학/성과 데이터 수집을 추가하지 않는다.
6. 기존 관리자 및 계정 허용 조건을 매 호출 검증하고 비관리자 접근을 거부한다.
7. 잔액은 기존 공식 계산 함수의 파생 조회값이다.

## 복구
